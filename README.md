# ZenMoney Analytics

Веб-приложение для аналитики по выгрузке транзакций из [ZenMoney](https://zenmoney.ru). Загрузите CSV-экспорт — и смотрите, куда уходят деньги, как меняются траты по месяцам и сколько приносит пассивный доход.

- Вход по email и паролю, можно привязать **passkey** (вход по отпечатку, лицу или PIN-коду устройства).
- Данные хранятся в **SQLite** в одном файле.
- Запускается одним **Docker**-контейнером; образ публикуется в `ghcr.io/artempas/zenmoney_analytics`.

## Дашборды

| Дашборд                       | Что показывает                                                                                                                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Обзор периода**             | Доходы, расходы (за вычетом возвратов), сбережения и норма сбережений с изменением к прошлому периоду; накопленные расходы по дням против среднего за 3 предыдущих месяца; прогноз расходов до конца текущего месяца; топ категорий. |
| **Динамика по месяцам**       | Доходы и расходы, сальдо и накопленный итог, стек расходов по категориям, тренд выбранной категории за 6/12/24 месяца.                                                                                                               |
| **Календарь трат**            | Тепловая карта трат по дням (клик — операции дня), средние траты по дням недели, матрица «день недели × час».                                                                                                                        |
| **Поток денег**               | Sankey: источники дохода → бюджет → категории и подкатегории расходов, переводы в накопления, остаток.                                                                                                                               |
| **Крупные и необычные траты** | Операции, заметно превышающие обычный чек у того же получателя или в той же категории; всплески категорий к среднему за 3 месяца; топ-20 крупнейших трат.                                                                            |
| **Доходы и пассивный доход**  | Источники дохода по месяцам; проценты и кэшбэк нарастающим итогом, их доля и годовой темп, разбивка по счетам.                                                                                                                       |

Кроме дашбордов есть таблица транзакций с фильтрами и поиском, где можно вручную поменять тип операции, страница загрузки и настройки. У каждого графика есть табличное представление.

## Быстрый старт

```bash
docker run -d --name zenmoney-analytics \
  -p 3000:3000 \
  -v zenmoney-data:/data \
  -e APP_ORIGIN=http://localhost:3000 \
  ghcr.io/artempas/zenmoney_analytics:latest
```

Откройте <http://localhost:3000>, зарегистрируйтесь (первый пользователь регистрируется свободно, после него регистрация закрывается) и загрузите выгрузку на странице «Загрузка выгрузки».

Или через Docker Compose — см. [`docker-compose.yml`](docker-compose.yml):

```bash
docker compose up -d
```

### Переменные окружения

| Переменная           | По умолчанию            | Описание                                                                                              |
| -------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `APP_ORIGIN`         | `http://localhost:3000` | Адрес, по которому открывается приложение. **Нужен для passkey**: они работают только на этом адресе. |
| `PORT`               | `3000`                  | Порт HTTP-сервера.                                                                                    |
| `DATA_DIR`           | `/data` (в образе)      | Каталог для базы `zenmoney.db`.                                                                       |
| `ALLOW_REGISTRATION` | `false`                 | Разрешить регистрацию новых аккаунтов после первого. Данные разных аккаунтов изолированы.             |
| `TRUST_PROXY`        | `false`                 | Включите за reverse proxy, чтобы учитывались `X-Forwarded-*`.                                         |
| `COOKIE_SECURE`      | авто                    | Флаг `Secure` у cookie; по умолчанию включён, если `APP_ORIGIN` начинается с `https://`.              |
| `SESSION_TTL_DAYS`   | `30`                    | Время жизни сессии.                                                                                   |
| `RP_ID`              | хост из `APP_ORIGIN`    | Relying Party ID для passkey (обычно менять не нужно).                                                |
| `LOG_LEVEL`          | `info`                  | Уровень логов.                                                                                        |

### HTTPS и passkey

Браузеры разрешают passkey только в защищённом контексте: по **HTTPS** или на **localhost**. Если приложение доступно по домену, поставьте перед ним reverse proxy с TLS и укажите этот адрес в `APP_ORIGIN`. Пример для Caddy:

```
money.example.com {
  reverse_proxy zenmoney-analytics:3000
}
```

```yaml
environment:
  APP_ORIGIN: https://money.example.com
  TRUST_PROXY: 'true'
```

Если поменять домен, ранее привязанные passkey перестанут подходить — их нужно будет привязать заново.

### Резервная копия

Все данные — это файл `zenmoney.db` в томе `/data`. Для копии достаточно скопировать каталог (лучше при остановленном контейнере) или выполнить `sqlite3 /data/zenmoney.db ".backup backup.db"`.

## Как загружать данные

1. Экспортируйте транзакции из ZenMoney в CSV. Файл называется примерно `zen_2026-09-29_dumpof_transactions_….csv`.
2. Загрузите его на странице «Загрузка выгрузки».

Повторная загрузка **заменяет** операции за период, который покрывает файл (от первой до последней даты в нём). Поэтому можно регулярно выгружать, например, последний месяц: правки и удаления, сделанные в ZenMoney, тоже попадут в аналитику, а более ранние данные останутся.

> Выгрузка содержит персональные данные. Приложение хранит их только в вашей базе SQLite и никуда не отправляет.

## Как распознаются операции

В выгрузке тип операции задаётся заполненными полями: оба счёта — перевод, только списание — расход, только зачисление — доход. Но переводы между своими счетами в разных банках ZenMoney часто не связывает, и они выглядят как отдельные доход и расход. Поэтому для операций **без категории** с одним счётом применяются правила (первое сработавшее):

1. **Ручная правка** в таблице транзакций. Сохраняется при повторных загрузках.
2. **Пара встречных операций**: списание и зачисление в одной валюте на разных счетах с разницей в датах до 3 дней. Сначала ищутся точные совпадения суммы, затем расхождение до 5% (комиссия) для сумм от 1 000.
3. **Перевод себе**: получатель или комментарий содержит одно из «моих имён» из настроек (например `Иван П.`, `Иван Иванович П`).
4. **Операция на накопительном счёте** — перевод. Тип счёта определяется по названию (`накоп`, `вклад`, `копилка`, `депозит`, `брокер`, `…%`) и меняется в настройках.
5. Остальное учитывается как доход или расход «Без категории». Это можно отключить в настройках.

**Возвраты.** Поступление в категории, по которой были траты (друзья вернули долю за ужин, возврат покупки), уменьшает расходы этой категории, а не увеличивает доходы. Исключение — категории с «доходными» названиями (зарплата, проценты, кэшбэк, дивиденды и т. п.).

**Пассивный доход** — поступления в категориях с процентами, кэшбэком, дивидендами и купонами (список можно поменять в настройках), а также поступления без категории с такими словами в комментарии.

## Разработка

Нужен Node.js 22+.

```bash
npm install
npm run dev          # сервер на :3000 и Vite на :5173 (прокси /api → :3000)
npm test             # тесты сервера (Vitest)
npm run typecheck
npm run lint
npm run build        # server/dist и web/dist
npm start            # запуск собранного приложения
```

В режиме разработки приложение открывается на `http://localhost:5173`; чтобы работали passkey, запустите сервер с `APP_ORIGIN=http://localhost:5173`.

Локальная сборка образа: `docker build -t zenmoney-analytics .` (базовый образ можно заменить через `--build-arg NODE_IMAGE=…`).

Стек: TypeScript, Fastify, better-sqlite3 + Drizzle ORM, SimpleWebAuthn, React, Mantine, ECharts, TanStack Query.

```
shared/   типы API, общие для сервера и клиента
server/   Fastify API, импорт и классификация, аналитика, миграции (server/drizzle)
web/      React-приложение
```

Миграции БД генерируются из `server/src/db/schema.ts` командой `npm run db:generate --workspace server` и применяются автоматически при старте.

## Публикация образа

Workflow [`docker-publish.yml`](.github/workflows/docker-publish.yml) собирает образ на каждый push и PR, а публикует в `ghcr.io/artempas/zenmoney_analytics` при push в ветку по умолчанию (тег `latest`), при push тега `v*` (теги `1.2.3`, `1.2`) и при ручном запуске. Образ собирается для `linux/amd64` и `linux/arm64`.

После первой публикации проверьте, что пакет публичный: GitHub → профиль → Packages → `zenmoney_analytics` → Package settings → Change visibility → Public.
